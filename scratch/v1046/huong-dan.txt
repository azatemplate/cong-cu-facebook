================================================================================
1. CƠ CHẾ ĐIỀU PHỐI VÀ CHÍNH SÁCH BẢO MẬT (BYPASS CORS / CSP)
================================================================================
- Extension áp dụng cơ chế Waterfall (Fallback Chain): Khi có yêu cầu tải video,
  Service Worker (background.js) sẽ thử lần lượt từ Cách 1 -> Cách 2 -> Cách 3.
  Nếu một cách bị lỗi mạng, rate-limit hoặc dính Cloudflare, hệ thống tự động
  chuyển sang cách tiếp theo trong vòng tối đa 20 giây (_MEDIA_CHAIN_BUDGET_MS).
- Vượt rào CORS & CSP: Trang web tiktok.com áp dụng chính sách CSP (Content Security Policy)
  nghiêm ngặt. Để phát/tải được video từ các host bên ngoài, Service Worker nhận
  quyền host_permissions (*://*.tiktokcdn.com/*, *://*.muscdn.com/*, *://*.tikcdn.io/*...)
  sẽ fetch mảng byte ngầm và mã hóa Base64 thành Blob URL để trình duyệt phát trực tiếp.

================================================================================
2. CÁCH 1: TIKWM API (TIKWM.COM)
================================================================================
Đây là kênh giải mã mặc định có độ ưu tiên cao nhất, trả về dữ liệu đa dạng nhất.

* Endpoint: POST https://tikwm.com/api/
* Request Headers:
  - Content-Type: application/x-www-form-urlencoded
  - Accept: application/json, text/plain, */*
* Request Body:
  url={TIKTOK_VIDEO_URL}&hd=1

* Cấu trúc Response JSON trả về:
  {
    "code": 0,
    "msg": "success",
    "data": {
      "id": "7312345678901234567",
      "title": "Nội dung caption video...",
      "play": "https://tikwm.com/video/media/play/7312345678901234567.mp4",        // Link MP4 thường không logo
      "hdplay": "https://tikwm.com/video/media/hdplay/7312345678901234567.mp4",    // Link MP4 HD không logo
      "wmplay": "https://tikwm.com/video/media/wmplay/7312345678901234567.mp4",    // Link MP4 có logo
      "music": "https://tikwm.com/video/media/music/7312345678901234567.mp3",      // Link Audio MP3
      "cover": "https://p16-sign-va.tiktokcdn.com/...",                             // Ảnh bìa
      "images": [                                                                   // Ảnh nếu là dạng Slideshow/Photo
        "https://p16-sign-va.tiktokcdn.com/img1.jpg",
        "https://p16-sign-va.tiktokcdn.com/img2.jpg"
      ],
      "size": 15420100,                                                             // Dung lượng file MP4
      "hd_size": 28910200,                                                          // Dung lượng file HD
      "author": {
        "unique_id": "username_tiktok",
        "nickname": "Tên Người Dùng"
      }
    }
  }

* Quy trình xử lý mã nguồn:
  Hàm `_providerTikwm` gửi request fetch với timeout 9000ms. Kiểm tra nếu chuỗi JSON
  bị dính Cloudflare HTML ("Just a moment...") thì ném ra lỗi để chuyển sang Cách 2.

3. CÁCH 2: SNAPCDN / TIKDOWNLOADER / TIKVID API (AJAXSEARCH + DECODE JWT)
================================================================================
Sử dụng khi TikWM bị chặn IP/Cloudflare. Kênh này khai thác hệ thống backend SnapCDN.

* Các Host áp dụng:
  - tikdownloader.io
  - tikvid.io
  (và các tên miền dự phòng white-label tương đương: tiksave.io, savetik.co)

* Endpoint: POST https://{host}/api/ajaxSearch
* Request Headers:
  - Content-Type: application/x-www-form-urlencoded
  - Accept: application/json, text/plain, */*
* Request Body:
  q={TIKTOK_VIDEO_URL}&lang=en

* Response JSON trả về:
  {
    "status": "ok",
    "data": "<div class=\"download-box\">...<a href=\"dl.snapcdn.app/get?token=eyJhbGciOi...\">Download</a>...</div>"
  }

* Thuật toán giải mã bóc tách link gốc trong `_parseAjaxSearchHtml` & `_snapTokenUrl`:
  1. Dùng Regex tìm các liên kết dạng: `dl.snapcdn.app/get?token=([A-Za-z0-9_.-]+)`
  2. Mã token này là một chuỗi JWT dạng `Header.Payload.Signature`.
  3. Extension bóc phần `Payload` (phần thứ 2 sau dấu chấm).
  4. Thay thế ký tự Base64URL: `-` -> `+`, `_` -> `/`, thêm ký tự đệm `=`.
  5. Giải mã Base64 chuỗi Payload ra đối tượng JSON:
     {
       "url": "https://v16m-default.tiktokcdn-us.com/video/tos/useast2a/...",
       "filename": "tiktok_video.mp4"
     }
  6. Kiểm tra URL lấy ra có thuộc danh sách host hợp lệ của TikTok không (tiktokcdn.com,
     tiktokcdn-us.com, tiktokv.com, muscdn.com...). Nếu đúng, dùng trực tiếp link CDN này.

4. CÁCH 3: TIKMATE API (TIKMATE.APP + FETCH MEDIA BLOB)
================================================================================
Kênh dự phòng thứ ba khi 2 kênh trên đều không trả về kết quả.

* Endpoint: POST https://api.tikmate.app/api/lookup
* Request Headers:
  - Content-Type: application/x-www-form-urlencoded
  - Accept: application/json, text/plain, */*
* Request Body:
  url={TIKTOK_VIDEO_URL}

* Response JSON trả về:
  {
    "success": true,
    "token": "ABC123XYZ_TOKEN",
    "id": "7312345678901234567",
    "desc": "Caption video...",
    "author_id": "username",
    "author_name": "Nickname",
    "like_count": 12500,
    "comment_count": 450
  }

* Cấu trúc URL Download được ghép lại:
  - Link Video Không Logo: https://tikmate.app/download/{token}/{id}.mp4
  - Link Video Có Logo:    https://tikmate.app/download/{token}/{id}-watermark.mp4

* Cơ chế xử lý byte ngầm (`FETCH_MEDIA_BLOB`):
  Do host `tikmate.app` không nằm trong danh sách trắng CSP của trang TikTok, thẻ `<video>`
  trên web sẽ bị chặn không cho phát trực tiếp link này.
  Service Worker thực hiện:
  1. `fetch("https://tikmate.app/download/...")` lấy luồng dữ liệu byte.
  2. Chuyển ArrayBuffer thành chuỗi Base64 (`_abToBase64`).
  3. Ép MIME-type thành `video/mp4`.
  4. Gửi chuỗi Base64 sang content script để tạo `URL.createObjectURL(blob)` giúp
     trình duyệt xem trước và tải xuống mượt mà.

5. CÁCH 4: TRA CỨU LUỒNG TIKTOK LIVE STREAM (ROOM INFO API)
================================================================================
Áp dụng khi người dùng muốn lấy link phát trực tiếp (Live Stream) từ một kênh TikTok.

* BƯỚC A: Tra cứu Room ID từ Username
  - Endpoint: GET https://www.tiktok.com/api-live/user/room/?aid=1988&sourceType=54&uniqueId={USERNAME}
  - Headers: Accept: application/json (credentials: omit)
  - Đọc từ Response: `data.user.roomId` hoặc `data.liveRoom.status` (status = 2 là đang live, 4 là đã kết thúc).

* BƯỚC B: Lấy thông tin luồng phát (Stream URLs) từ Room ID
  - Endpoint: GET https://webcast.tiktok.com/webcast/room/info/?aid=1988&room_id={ROOM_ID}
  - Trích xuất từ `data.stream_url`:
    + `flv_pull_url`: Mã hóa danh sách link FLV theo chất lượng:
      { "FULL_HD": "http://pull-flv...", "HD": "http://pull-flv...", "SD": "http://..." }
    + `hls_pull_url_map`: Mã hóa danh sách link HLS (m3u8):
      { "FULL_HD": "http://pull-hls...", "HD": "http://pull-hls..." }
    + `live_core_sdk_data.pull_data.stream_data`: Bóc tách chuỗi JSON lồng bên trong
      để lấy chính xác các link luồng m3u8/flv chất lượng cao nhất.

6. CÁCH 5: BÓC TÁCH GIỎ HÀNG TIKTOK SHOP & ẢNH SẢN PHẨM PDP
================================================================================
Nhiều video chứa giỏ hàng TikTok Shop nhưng giao diện Desktop bị TikTok ẩn link mua.

* BƯỚC A: Giả lập Mobile User-Agent bằng `declarativeNetRequest`
  - Extension thêm tham số `__tpt_mobile=1` vào URL.
  - File `net_rules.json` (Rule ID 3) tự động ghi đè HTTP Request Header `User-Agent`
    thành iOS Safari:
    `Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15...`
  - TikTok nhận nhầm request từ điện thoại di động nên trả về HTML Mobile có chứa
    thẻ giỏ hàng `<div class="DivEcomAnchorMobile">` và tham số `chain_key`.

* BƯỚC B: Đọc HTML Mobile tìm Anchor Sản phẩm (`_extractAnchorFromVideoHtml`)
  - Gửi request `GET https://m.tiktok.com/v/{id}.html` hoặc `https://www.tiktok.com/@user/video/{id}?__tpt_mobile=1`.
  - Quét Regex tìm link sản phẩm: `/href="([^"]*(?:\/shop\/[^"]*chain_key|\/pdp\/[^"]*|\/view\/product\/[^"]*|[?&]product_id=\d+)[^"]*)"/`
  - Đọc thông tin tên sản phẩm, giá bán, ảnh bìa từ thẻ HTML hoặc từ các block
    JSON-LD/Hydration ngầm trong trang.

* BƯỚC C: Quét Album ảnh sản phẩm qua Tab Ẩn Ngầm (`_fetchProductPageInBrowser`)
  - Nếu fetch URL sản phẩm bị dính Captcha ("Security Check"), Service Worker kích hoạt:
    1. Tạo một tab ngầm không active: `chrome.tabs.create({ url: productUrl, active: false })`.
    2. Tab này chạy bằng cookie thật của người dùng nên vượt qua được tường xác minh.
    3. Dùng `chrome.scripting.executeScript` để đợi slider ảnh (`.slick-slider img`)
       hoặc gallery hydrated xong, cào toàn bộ danh sách URL ảnh sản phẩm chất lượng cao.
    4. Tự động đóng tab ngay lập tức sau khi cào xong: `chrome.tabs.remove(tabId)`.

7. CÁCH 6: LẮNG NGHE LUỒNG API NGẦM TRÊN TRANG (HOOK.JS FETCH/XHR INTERCEPTION)
================================================================================
Đây là cách thụ động nhưng cực kỳ hiệu quả, hoạt động liên tục khi người dùng xem TikTok.

* Cơ chế tiêm code vào trang (`hook.js`):
  Extension tiêm `hook.js` vào ngay `document_start` chạy ở môi trường Main World.

* Ghi đè phương thức mạng gốc của trình duyệt:
  - `const _realFetch = window.fetch;`
  - `const _xhrOpen = XMLHttpRequest.prototype.open;`
  - `const _xhrSend = XMLHttpRequest.prototype.send;`

* Luồng xử lý:
  1. Khi người dùng lướt feed, TikTok tự động gọi API lấy các video tiếp theo.
  2. `hook.js` bắt được kết quả trả về của `fetch` và `XHR`.
  3. Lọc các URL khớp với API feed: `/api/(recommend|item|post|related|shop|search)/`.
  4. Đọc chuỗi JSON kết quả, tự động chạy hàm `_harvestFromJson`:
     - Gom `aweme_id` -> chỉ số view, like, share, comment.
     - Gom `aweme_id` -> giỏ hàng, thông tin sản phẩm đính kèm.
  5. Bắn sự kiện `CustomEvent('tpt-video-map-update')` và `CustomEvent('tpt-product-map-update')`
     để gửi dữ liệu sang `content.js`.
  6. Nhờ vậy, khi người dùng bấm Tải hoặc bấm xem chỉ số, dữ liệu đã có sẵn trong bộ nhớ
     mà không cần gửi thêm bất kỳ request mạng nào ra bên ngoài!
